# Knowledge Maintain

Bring published knowledge into agreement with the supplied change and its evidence. Read [publication rules](../../references/publication.md) before editing. Read [repository integration](../../references/repository-integration.md) when navigation or host instructions need repair; read [continuity](../../references/continuity.md) if an investigation needs to be saved or closed.

## Find affected knowledge

Preserve the original request and supplied change scope. Read applicable instructions and navigation. Inspect the supplied diff or relevant Git changes, including uncommitted work, and affected code and tests. Follow behavior IDs, paths, and symbols to related pages, shared explanations, and incoming links.

If the change boundary cannot be established, ask for that missing boundary while completing independent inspection. Do not treat every repository difference as part of the request.

## Reconcile and publish

Update the authoritative explanation where possible. Correct affected conditions, results, examples, implementation flow, code/test references, and navigation. Preserve unrelated content. Keep a behavior's ID when its identity persists through wording, location, or implementation changes; never recycle an ID for unrelated behavior. Explain splits, replacements, or retirements when needed to keep old references understandable.

Distinguish observed implementation, test intent, executed checks, confirmed intent, and proposed changes. When sources conflict, show the disagreement and ask only for decisions that evidence cannot resolve. Publish independent supported updates while preserving necessary unresolved context. Do not silently rewrite a confirmed requirement to match code or label a working-branch change as merged or deployed.

Run relevant existing checks when useful and authorized. Record what ran and what was unavailable. A test reference is not evidence of execution. Do not install dependencies, fix the application, or alter test infrastructure unless separately authorized.

If established knowledge is missing, publish the bounded findings needed for this request or suggest Discover for broader preparation; do not silently expand into a full investigation.

## Check and finish

Verify changed references against actual files and symbols, follow affected links, and review the diff for omissions, duplication, and unrelated edits. Close completed investigation records only after publishing conclusions and preserving remaining work elsewhere.

If current documents already express the supported facts and their references resolve, leave them unchanged and report no update needed. Do not rewrite prose, rotate IDs, or refresh document timestamps merely because the skill ran again. Preserve useful provenance of earlier check results; record genuinely new verification evidence without needless churn in knowledge pages.

Return a short complete, partial, or blocked result with links to changed pages and necessary remaining work. Resolve resources relative to this skill directory. Generated knowledge belongs in the investigated repository, never in the plugin installation.
